# T5 draft dan pemulihan implementation plan

> For agentic workers: use superpowers:executing-plans. Pengguna sudah meminta implementasi lanjutan; kerjakan langsung dalam worktree yang ada.

**Goal:** Form, foto dan kiriman tertunda pulih setelah reload tanpa mengganti UUID atau menimpa tab lain.

**Architecture:** Satu modul IndexedDB native menyimpan snapshot formulir dan byte JPEG dalam transaksi dengan pemeriksaan revisi. Web Locks menjaga satu pengirim foreground; UUID kiriman disimpan sebelum request pertama. Service worker hanya menyimpan shell/aset aplikasi, sedangkan daftar lokasi tervalidasi disimpan di IndexedDB.

**Tech stack:** Next.js/React/TypeScript yang ada, IndexedDB, Web Locks, Cache Storage; fake-indexeddb hanya untuk check Node (Node tidak menyediakan IndexedDB).

**Spec:** docs/plan.md §9 dan T5; README.md keputusan pengguna terbaru (tanpa aktivasi, nama manual, UTM fleksibel).

## Global constraints

- T5 saja; T6/T7, login dan izin foto tidak ditambahkan.
- Maksimal lima JPEG; schema checklist 2 dan template 2026-10-09.draft1 tetap.
- Draft belum lengkap boleh disimpan; Kirim wajib lokasi terkonfirmasi/checklist valid.
- Penyimpanan penuh/ditolak tidak boleh menampilkan berhasil atau menghapus salinan sebelumnya.
- Foto privat, respons inspeksi dan request API tidak masuk cache service worker.
- Tidak ada perubahan Apps Script yang diperlukan oleh T5. Finalisasi T4 Google asli tetap harus dibuktikan.

## Review focus

- Dua tab mengedit revisi sama: satu berhasil, tab lain menahan isian dan menawarkan pemulihan.
- Respons finalisasi hilang: byte/UUID tetap, retry idempoten; bersihkan byte hanya bersama acknowledgment terverifikasi.
- Kuota storage/transaksi abort: tidak mengklaim draft aman atau mengirim tanpa snapshot durable.
- Lokasi mentah belum dikonfirmasi dan pengukuran belum lengkap pulih tanpa menjadi hasil valid otomatis.
- Upgrade aplikasi dan kegagalan salah satu aset: readiness tidak muncul sampai shell/template/master benar-benar tersimpan.
